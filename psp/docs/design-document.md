# Дизайн-документ Dropnetgaming

## 1. Название проекта
Dropnetgaming — CS2 Match Hub.

## 2. Краткое описание идеи
Игровая платформа для CS2: регистрация игроков, поиск матча, ELO, уровни, задания, команды, турниры, новости, обращения и админ-панель.

## 3. Коммерческая цель
Сайт должен зарабатывать через:
- Premium-подписку;
- заявки на турниры;
- рекламные размещения для партнёров;
- продвижение команд и игровых сервисов.

Целевые действия: регистрация, оформление Premium, заявка на турнир, обращение в поддержку, партнёрская заявка.

## 4. Целевая аудитория
- игроки CS2 14–25 лет;
- капитаны команд;
- начинающие киберспортсмены;
- организаторы турниров;
- рекламодатели игровых сервисов.

## 5. Персонажи
1. Игрок: хочет быстро найти матч и прокачать ELO.
2. Капитан команды: хочет собрать состав и подать заявку на турнир.
3. Партнёр: хочет купить рекламное размещение.
4. Администратор: хочет управлять новостями, обращениями и пользователями.

## 6. Пользовательские сценарии
- Контекстный: игрок заходит вечером, входит в аккаунт и ищет матч.
- Ключевой путь: регистрация → поиск матча → результат → изменение ELO → профиль.
- Проверочный: если пользователь не вошёл, сайт отправляет его на страницу входа; если форма пустая, показывает ошибку.

## 7. Информационная архитектура
Гибридная структура:
- Главная / матчмейкинг
- Играть
- Комната матча
- Premium
- Турниры
- Команды
- Лидерборд
- Новости
- Обратная связь
- Админ-панель
- Документы проекта
- Контакты
- Политика

## 8. Основные страницы
См. `docs/sitemap.md`.

## 9. Функциональные блоки
- авторизация;
- поиск матча;
- ELO и уровни;
- новости через админку;
- ежедневные задания;
- лидерборд;
- обращения;
- Premium;
- партнёрские заявки.

## 10. Frontend
React + Vite. Отдельные страницы и компоненты. Адаптивная верстка. Состояния форм, кнопок и таблиц.

## 11. Backend
В учебной версии backend имитируется через localStorage. Данные: пользователи, сессия, новости, обращения, матчи, задания, результаты тестирования.

## 13. Критерии готовности
- сайт запускается;
- страницы разделены по файлам;
- навигация работает;
- формы сохраняют данные;
- админ управляет контентом;
- есть адаптивность;
- есть документация проекта.
